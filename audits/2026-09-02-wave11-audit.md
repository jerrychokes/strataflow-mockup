## Findings

### W11-A-1 · P3 — "Principals seen" is computed one qualifier narrower than its printed definition

- **Evidence:** `screens.mjs:4582` — `seen = (b) => MEMBERS.filter((m) => m.group ===
  b.group && m.state === 'active').length` — while the paragraph under the table defines
  the number as "principals this instance has actually seen, whose membership resolved to
  the binding at that moment". J. Halloran *was* seen (2026-07-30, as a WDL Contributor)
  and is excluded by the `state === 'active'` clause, so the Contributors row reads 2
  where the printed definition yields 3. Screenshot: `1280-roles-bindings.png`.
- **Expected:** the count and its definition agree. **Observed:** the implementation
  silently adds "…and still holds it".
- **Recommended correction:** either count ever-seen (matching the sentence, and letting
  the deprovisioned row demonstrate that history survives removal — which is the
  register's own theme), or amend the sentence to "…and whose binding is still active".
  One line either way.

### W11-A-2 · P3 — One not-in-v1 citation paraphrases the test a word wider than the test asserts

- **Evidence:** the no-consultancy-identity panel says the provisioning suite asserts no
  binding column "names a person, a user, a member, a subject or an email";
  `provisioning.spec.ts:763` asserts `/principal|user|member|subject|email/`. Four of the
  five words are the test's own; "a person" stands in for "principal". A column named
  `person_id` would pass the test while violating the sentence — exactly the
  checkable-claim class wave 10 was held to.
- **Expected:** the paraphrase no stronger than the assertion. **Observed:** one word
  stronger. **Recommended correction:** say "a principal" (or extend the test's regex
  with `person`, which would make the sentence true the other way).
