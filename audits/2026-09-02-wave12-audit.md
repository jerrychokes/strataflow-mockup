### W12-A-2 · P1 — The screen says the release publishes signed build provenance; the release's own file says it currently attests nothing

- **Reproduction:** `#package` renders "A checksum, not a signature. **The release
  publishes signed build provenance for the two images it builds** and for nothing else —
  configuration is not one of them…" (from the seed's anchor bullet at seed.mjs:7825–7827).
  The named source, `.github/workflows/release.yml`, conditions both attestation steps on
  `!github.event.repository.private` and its comment records the reality: "the images
  pushed, then `attest` failed with *'Feature not available for user-owned private
  repositories'*… **these images carry no attestation, and nobody should verify one that
  was never written**."
- **Grading:** the operative claim (configuration is checksummed, never signed; the only
  provenance path that exists at all targets exactly the two image digests) is true and
  verified. The clause "publishes signed build provenance" is false of the repository as
  it stands, against an anchors block whose own preamble is "Nothing below is drawn from
  memory. Each of these was read in the app repo." Not graded P0 because it contradicts no
  other drawn screen and the falsehood strengthens rather than weakens the screen's
  argument (today *nothing* is signed, which is more reason a checksum is not a
  signature) — but it blocks the gate as a P1 all the same.
- **Recommended correction:** one clause — e.g. "the release declares signed build
  provenance for the two images it builds and for nothing else — and on this repository
  even that is skipped, so today nothing is signed at all; configuration has no signing
  step either way." Fix the seed bullet in the same edit.
