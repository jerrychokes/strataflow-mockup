## Findings

### W17-A-1 · P2 — The "as drawn until 3 Sep" history re-derives from the present for one of its four rows

- **Where:** `seed.mjs`, `QUALIFIERS.drawnBefore[0].was.code`, which is `fd2.qualifier` — a
  live read. The other three rows carry literals (`'H'`, `'*'`, `'D'`).
- **Reproduction:** in a copy of `head`, set `FD-2`'s `qualifier: 'J'` → `'U'` (`seed.mjs:1948`;
  `'U'` keeps the letter-collision non-empty so the build survives), `node build.mjs`, then read
  `#qualifiers`. The panel headed *"What this screen drew until 3 September 2026"* now reports
  the Zinc·MW05 row as having been drawn with code **`U`**. It was drawn with `J` — the baseline
  literal at `01a3ac7 screens.mjs:2121` says so. The verdict cell still reads "the code is right
  and the asserter is not", which under that record would also be false.
- **Expected:** a *before* is history and cannot be rewritten by a later record — the convention
  this wave itself follows everywhere else (`schemeWas: 'USEPA'`, `wave10.was`, the byte-exact
  blockquote, the `source`-until-3-Sep label).
- **Observed:** one field of one before is a pointer at the present, on the panel whose entire
  subject is that befores must not be silently repaired.
- **Severity reasoning:** P2, not higher — at `5759068` the panel renders **correctly**
  (`fd2.qualifier === 'J'`), so nothing false is drawn today and no acceptance criterion fails.
  Not P3 either: it is a traceability defect on a traceability surface, and it defeats the
  panel's own guarantee.
- **Correction:** make it the literal `'J'`, as its three siblings are. If the intent was to
  demonstrate the code is right, keep the literal for the *drawn* value and add a separate
  derived assertion (`stands: fd2.qualifier === 'J'`) rather than conflating the two.

### W17-A-2 · P3 — Two derived collections are consumed unguarded, so a plausible future record kills the build

Both fail loudly rather than printing a falsehood, which is why this is P3.

- **(a)** `seed.mjs:9696` indexes `QUALIFIERS.collisions[0].code` with no guard, while the
  record's own comment three hundred lines earlier presents that collection as *"Derived rather
  than pointed at: today it returns one group and it is `J`"*. Derived-ness is the point, and
  `[0]` spends it. **Reproduction:** set `PFAS_LIMITS.qualifier: 'J'` → `'UJ'`, `node build.mjs`
  → `TypeError: Cannot read properties of undefined (reading 'code')`. The letters simply stop
  colliding, which is a legitimate future record, not a corrupt one.
- **(b)** `screens.mjs:1886-1892` maps `QUALIFIERS.raisedHere` and dereferences `r.finding`, but
  `raisedHere` is defined as `rows.filter(r => r.origin !== 'laboratory')` — "not laboratory
  origin", which is not the same predicate as "came from a QA/QC finding". The two coincide only
  because every non-laboratory row happens to be a finding today. **Reproduction:** set
  `RESULT_DETAIL.qualifiers[0].origin` to `'manually'` — the glossary's own second origin word,
  describing exactly a practitioner-applied qualifier — and `node build.mjs` dies with
  `TypeError: Cannot read properties of undefined (reading 'check')` on `#qc`.
- **Correction:** guard the index (`collisions[0]?.code`, with the sentence degrading to the
  no-collision case), and either filter `raisedHere` on the presence of `finding` or give the
  screen its own predicate that says what it means.
